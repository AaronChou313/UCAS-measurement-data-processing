# 课程可视化组件设计与验收规范

适用范围：本课程 VitePress 教材后续可视化。依据 V01、V18、V14 首批试点及第一阶段打磨形成；不改变六章知识顺序，不把新增教学图标为教师考点。

本规范约束数学对象、读者任务与验收方法。它不规定每章图数，也不是通用前端框架。实际试学反馈仍可修订教学取舍。

## 1. 先确定读者需要完成什么

给每项候选写一句可检查的学习任务，而非“让页面更丰富”。先读该小节及前后衔接，再选最简单的表达形式。

| 障碍与目标 | 首选形式 | 本次验证与边界 |
|---|---|---|
| 同一对象换坐标，或不同操作改变对象 | 并列静态 SVG | V01 的固定终点与两套构造无需按钮。颜色和线型明确区分原基、新基、构造与对象。 |
| 计算有明确输入、来源与输出 | 手动分步 | V18 将来源乘积与按行求和分开。可以前进、回退，不用连续动画插入不存在的离散状态。 |
| 需要检验一个参数的影响 | 单参数交互 | V14 固定均值、边缘标准差和概率，只改变相关系数。先预测，再操作，再联系公式。 |
| 符号或概念区别不清 | 先改文字或局部对照 | 用二维矩阵、列向量及量/单位表解决问题，不额外制作动画。 |

只有静态图、相邻静态步骤都不足以说明连续变化时，才考虑播放动画。只有不可替代的三维关系才考虑 3D。本阶段没有增加动画、3D、随机点云或新可视化项目。

## 2. 与正文的组织方式

1. 图前用一至两句话说明当前问题和需要观察的差异。沿用附近数例，说明哪些参数固定。
2. 图中让输入、数学运算、输出有不同角色标签。复杂解释放在可读的 HTML 中，避免挤进小 SVG。
3. 图后说明一个可迁移的数学规律及其边界，必要时与前后推导连接。
4. 次要推导可以折叠；定义、关键输入、当步来源、主要输出必须无需打开折叠即可理解。
5. 同一公式可以在新语境提醒含义，但不把三段重复文字当成三个教学步骤。

V01 将小字号的图内说明移到面板下方，保留列向量公式；V18 用动作名称告诉读者下一步将计算什么；V14 将概率尺度放在图与读数表之间，直接解释主轴长度为何乘平方根。

## 3. 数学排版与符号

- 遵循 `系统学习笔记/00_阅读指南与统一符号.md`。向量使用粗体及列形式，矩阵与标量不能靠读者猜测。几何点的有序坐标对可以写 `(x,y)`，但不要把它当成未注明方向的向量排版。
- Markdown 正文继续使用 `$...$`、`$$...$$` 与现有 MathJax。不得把动态美元符号字符串插入页面并假定自动渲染。
- 小型动态矩阵使用 `MathMatrix.vue` 的二维 CSS 网格、矩阵括号和行序读屏名称；列向量传入 `[[x],[y]]`，不再追加转置。输入必须是非空、规则矩形数组，单元格为有限数值或明确的短数学表达式。
- 示例：`<MathMatrix :rows="matrixRows" label="当前总体协方差矩阵" :cell-chars="6" />`。`cellChars` 为显示宽度，不修改数值；连续变化且可能出现负号时，应预留最长数字宽度。
- `edu-root` 的被开方部分有上横线；`edu-fraction` 将分子与分母上下排列。上下标用 `<sub>`、`<sup>`，转置使用直立 `T`；符号不是普通正文中的装饰字母。
- 理论恒等式用 `=`。显示的有限小数与舍入计算用 `≈`，并说明内部计算保留全精度。不可因排版把近似变成精确等式。
- 数字只在显示边界格式化。使用 `formatNumber` 统一小数位、负零处理；不把格式化后的字符串反馈给模型。柱长、路径、矩阵和读数均来自同一数学模型。
- 不引入运行时公式库解决普通 2×2 数值矩阵；复杂公式先由正文渲染，确需动态公式时另外评估性能、回退与可访问性。

## 4. 颜色、线型与标签

以 `.vitepress/theme/visualizations/visualizations.css` 为局部视觉基础。它沿用站点主题，不影响全站导航或正文外观。

| 角色 | 浅色 / 深色 | 配套表达 |
|---|---|---|
| 主要对象或输出 | `#226451` / `#86d4b7` | 实线、明确名称或数值 |
| 辅助构造、主轴或第二来源 | `#3b65a0` / `#a3c4f5` | 角色文字；需要时用不同线型 |
| 基方向、观察方向 | `#855224` / `#edbd84` | 箭头及基/方向符号 |
| 参考轴或参考轮廓 | `#707a81` / `#99a4ac` | 细线、虚线或点线 |

颜色含义在每幅图的局部图例中声明，不能假设读者记住跨章节的颜色。绿色概率贡献和绿色几何对象不是同一个数学量。线型、名称、数值必须足以独立表达区别。

- 正文和公式的颜色使用站点文字变量。每轮检查两主题下的文本对比度与描边对比度；目标为正常文字至少 4.5:1、必要图形至少 3:1。
- 同色不同对象使用不同线型。V14 的蓝主轴、灰内虚线、点线外切框分别有图例；不会把内轮廓和主轴都画成相同蓝虚线。
- 标签贴近对象但不压在曲线、刻度和箭头上。必要时缩短图内标签，把完整说明移至 HTML 图例。
- V01 的棕色基箭头表示“一份基向量”，蓝色首尾构造表示倍数与平移后的分量；基向量不自动具有单位长度。
- 静态 SVG 使用 `<title>`、`<desc>`；按标题与说明理解图形不应依赖颜色。

## 5. 坐标、单位与尺度

- 几何长度需要相同横纵比例。不要靠不等比例轴制造旋转、细长或相关性的错觉。
- 比较参数时尽可能固定坐标范围；必须改变范围时明确标注。V18 的概率纵轴固定 0—1，横轴扩展会在图注说明。
- 坐标轴标变量与单位。C 的元素单位是 m²，特征值也是 m²，标准差和半轴是 m；角度进入三角函数前转换为弧度，图示可以标度数。
- 投影标准差、主轴标准差、概率半轴及射线半径是不同对象，不能用同一个“半轴”混称。
- 图形只是数值绘制，不是数学证明。曲线顶点、像素离散、浮点和显示舍入都有数值精度；验收用解析式与容差，不用“看起来像”作结论。
- 随机模拟须注明模型、种子、样本量、抽样误差；本批不用随机模拟证明理论覆盖概率。

### V14 现有几何工具的范围

`covarianceEllipse` 描述均值为零、坐标标准差为 $2\,\mathrm m$ 和 $1\,\mathrm m$ 的已知二维 Gaussian：

$$
C(\rho)=\begin{pmatrix}4&2\rho\\2\rho&1\end{pmatrix}\,\mathrm m^2.
$$

当前组件的相关系数范围为 $[-0.95,0.95]$，内部概率固定为 $0.95$。

`covariancePlot` 的概率面板坐标范围按 q=0.95 设计；传入其他 q 会拒绝计算，不能直接当通用椭圆组件复用。若扩展参数，先重做范围、标签、奇异/圆形边界与数学测试。`CovariancePlot.vue` 接收明确的 `idPrefix`，重复使用时必须给不同前缀。

样本参数代入椭圆、均值置信区域、新观测预测区域不能套用已知参数的 χ² 概率解释。W06 已在正文与 L08 说明中澄清；后续扩展须另外核实有限样本校正。

## 6. 交互与状态恢复

- 控件最少且动作明确。V18 用“显示来源贡献”“合计下一分布”“进入下一时刻”，不让同一个“下一步”隐藏实际操作。
- 当前输入与下一输出分别标明时间下标，不能把来源乘积画成已完成的概率分布。
- 单步状态机先定义合法状态、边界和逆操作。`navigateMarkov` 只服务 V18 的 k=0—60、三个阶段，不直接改名充当 Kalman 通用状态机。
- 改模型或初分布后从 k=0 清空历史重算。V18“恢复默认”回到城市、0.8及第一阶段；V14 恢复 ρ=0.50。不要用一个不明确的“重置”同时表达两种含义。
- 原生按钮和控件目标至少 44 px，可键盘操作，有可见焦点。静态公式和不滚动的表格不增加无用 Tab 停靠点；可横滚的大表保留键盘焦点与操作提示。
- 状态播报简洁，包含时刻/阶段与关键输入/输出；滑块在完成调节时播报结果，避免连续拖动时整张表反复朗读。
- 本批不自动播放、不增加运动；如以后播放，另行提供暂停、回退、重播、进度与减少运动支持。

## 7. 手机、主题与可访问性

- 先保证 390 px 视口，再检查 320 px 的窄屏、中间宽度及桌面。实际 SVG 字号是 `font-size × 显示宽度 / viewBox宽度`，不能只看源代码里的 18px。
- 关键图内标签以缩放后约 12px 为最低目标，手机通常更大。长说明应移到 HTML；图例用正文大小，不能把一整段缩进 SVG 后缩小。
- 对照图在宽屏并列、窄屏纵向排列。几何 SVG 保持比例；矩阵有稳定单元格宽度，参数变号不应突然推动整张图。
- V14 的常用读数用两列：量/公式与值；行名自然换行，成对数值分别排列，手机不用来回横滚。V18 长期多时刻表确实需要横滚，只滚表，不撑宽整页。
- 不能只检查默认参数。负相关、零相关、边界、不同 Markov 初值和终点都要看。
- 每个矩阵有行数、列数及逐行读法；SVG 有标题/说明。此处的语义检查不等同于已经做过屏幕阅读器人工听读。
- 本批实际浏览器检查以 Codex 内置浏览器为准；其他浏览器和辅助技术若未实测，验收记录必须写明。

## 8. 静态回退与实例

- 首屏核心知识存在于服务端 HTML；控件在挂载后出现。无 JavaScript 时不能留下“点击下一步”但没有按钮的死指令。
- V18 回退包括完整四个来源贡献、两个结果向量与收敛/不收敛对比，默认展开；V14 回退是默认矩阵、图、尺度表及解释。
- 不能只提供一张占位图或一条“需要 JavaScript”提示。回退应让读者完成主要阅读任务。
- SVG 的 title/desc、marker、aria-labelledby 等 ID 在同页必须唯一；新实例使用独立前缀。现有 V01 同页每个 kind 仅实例一次，跨页引用不受此限制。
- 公式和图在打印/断网阅读时的核心内容不应需要在线请求。当前没有专门的打印分页验收，不能承诺已验证全部打印布局。

## 9. 数学、SVG、静态页面与发布门禁

以下执行顺序固定，构建只做一次：

```sh
npm run test:visualizations
npm run figures:check
npm run docs:build
npm run check:visualization-pages
git diff --check
```

- 数学测试覆盖独立闭式、概率守恒、列方向、正定性、特征方程、投影极值和覆盖积分，不能只对实现本身写同义断言。
- 检查真实 SVG 的端点、坐标映射、marker引用、实例ID、生成结果；`figures:check` 只读，缺图不能自动生成后假装通过。
- 分步组件测试真实使用的导航函数，走过全部阶段、到上限、逆操作、恢复与非法状态。
- 参数组件测试全部 UI 档位、非法值、退化边界以及实际 SVG 路径和数值所用的同一模型。
- 页面检查读取构建后的 HTML：解析二维矩阵/列向量单元格、验证实际路径及来源乘积、静态回退展开、实例ID与控件条件，不只匹配几个中文标题。
- 所有新测试要纳入 `test:visualizations` 或另一条明确的 CI 门禁；不要新增文件却没执行。
- `.github/workflows/deploy-pages.yml` 的数学、SVG、单次构建及页面检查全部通过后，才上传 Pages 制品。部署依赖 build；没有 `continue-on-error` 或绕过失败的 `always()`。
- PR 运行同一验证链，但不上传 Pages 制品或部署。发布权限仅在主分支部署任务中使用；审阅分支工作流手动运行也不能部署。

## 10. 新组件的最小交付流程

1. 写清原文定位、读者问题、最简形式、对象/符号/单位、模型假设及预期观察；注明解释补充范围。
2. 在首次需要的位置放入组件，保留原知识、标题、锚点及来源。建立默认静态回退，再增加必要控件。
3. 将模型、显示格式与 SVG 对齐；提供独立数值验证和非法输入检查。小型共性可复用，领域逻辑不要为了“通用”被隐藏。
4. 实际走完首次阅读、操作、回退和恢复；检查桌面/手机、浅/深主题、关键参数、键盘、ID、控制台、公式及页面滚动。
5. 运行上述门禁一次完整链；保存代表截图，记录实际运行结果、浏览器与未验证范围。若改代码修复，再只重跑受影响项与最终发布门禁。
6. 做第二遍批判性检查：先从画面和公式找误导，再反查状态与实现。发现问题直接修复；教学取舍留给实际试学。
7. 更新试点/建设记录，提交审阅分支。用户确认后再合并发布；不要把 CI 通过等同于初学者学习效果已证实。
